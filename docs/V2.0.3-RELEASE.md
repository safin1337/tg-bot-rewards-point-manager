# SoulShop V2.0.3 release runbook

## Scope

V2.0.3 adds the active operation name to the customer-selection panel for
Record Purchase, Add Points Manually, Redeem Points, Check Balance, and
Customer History. The Add New Customer feature is unchanged.

This release changes Worker code, tests, and documentation only. It contains no
new D1 migration and does not require webhook or Telegram command changes when
the existing production Worker URL and secrets remain unchanged.

## 1. Prepare the release commit

From a clean checkout of `main`, install the locked dependencies and run every
required check:

```powershell
npm ci
npm run db:migrate:local
npm run typecheck
npm run lint
npm run test:run
npm run build
git check-ignore -v .dev.vars
git check-ignore -v migrations/0001_initial_schema.sql
git status --short
```

Inspect the diff and confirm that no secret, generated CSV, backup, `.dev.vars`,
`.env`, Wrangler state, coverage, or build artifact is staged. Commit the
release as one change:

```powershell
git add src/telegram/messages.ts src/workflows/common.ts tests/utils-messages.test.ts tests/workflows.test.ts package.json package-lock.json README.md CHANGELOG.md docs/DATABASE.md docs/TELEGRAM-WORKFLOWS.md docs/V2.0.3-RELEASE.md
git commit -m "feat(telegram): label customer selection by operation"
```

## 2. Verify Cloudflare access and D1 readiness

Authenticate with the intended Cloudflare account and inspect the production
migration status:

```powershell
npx wrangler whoami
npx wrangler d1 migrations list soulshop-rewards-db --remote
```

V2.0.3 adds no migration, but the remote database must already have every
migration through `0006_bounded_operational_storage.sql`. If `0006` is pending,
stop and follow [the V2.0.2 migration hotfix runbook](V2.0.2-MIGRATION.md)
before deploying the Worker.

Confirm that the three production secrets already exist without displaying
their values:

```powershell
npx wrangler secret list
```

Do not replace `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, or `WEBHOOK_SECRET` for this UI
release unless the production configuration itself needs to change.

## 3. Publish the Git release

Push the reviewed commit and create a new immutable patch tag:

```powershell
git push origin main
git tag -a v2.0.3 -m "SoulShop Rewards Point System v2.0.3"
git push origin v2.0.3
```

Never move or reuse the existing `v2.0.2` tag.

## 4. Deploy the Worker

Deploy only after the release commit, validation, D1 status, configuration, and
secrets have been verified:

```powershell
npm run deploy
```

This invokes `wrangler deploy` against the root `soulshop-rewards` Worker and
the D1 binding declared in `wrangler.jsonc`.

## 5. Verify production

Check the Worker health endpoint:

```powershell
Invoke-RestMethod "https://soulshop-rewards.<YOUR-SUBDOMAIN>.workers.dev/health"
```

Inspect the existing Telegram webhook without changing it:

```powershell
$env:BOT_TOKEN = "YOUR_BOT_TOKEN"
npm run telegram:webhook-info
Remove-Item Env:BOT_TOKEN
```

Using only the configured administrator account, verify that these dashboard
buttons show the expected bold heading above `Select a customer:`:

- `🛒 Record Purchase`
- `➕ Add Points Manually`
- `🎁 Redeem Points`
- `💰 Check Balance`
- `📜 Customer History`

Also verify `/purchase`, `/addpoints`, `/redeem`, `/balance`, `/history`, and
`/restart`, then open Add New Customer and confirm its existing prompt is
unchanged. Complete one read-only balance/history check before attempting any
live reward mutation.

The existing webhook does not need to be registered again when its URL and
secret are unchanged. Register it only for a new or changed production URL:

```powershell
$env:BOT_TOKEN = "YOUR_BOT_TOKEN"
$env:WEBHOOK_SECRET = "THE_SAME_SECRET_STORED_IN_CLOUDFLARE"
$env:PUBLIC_WORKER_URL = "https://soulshop-rewards.<YOUR-SUBDOMAIN>.workers.dev"
npm run telegram:set-webhook
Remove-Item Env:BOT_TOKEN
Remove-Item Env:WEBHOOK_SECRET
Remove-Item Env:PUBLIC_WORKER_URL
```

## 6. Roll back if necessary

Because V2.0.3 has no database migration, the Worker can be rolled back without
a D1 reversal:

```powershell
npx wrangler versions list
npx wrangler rollback
```

After rollback, repeat the health and webhook-status checks. Do not move or
delete the Git release tag; document the rollback and prepare a new patch
version for any correction.
